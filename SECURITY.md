# Security policy

## Sensitive data

Contracts can contain personal data, bank details, trade secrets, pricing, security commitments, and privileged material. Use synthetic or fully anonymized examples in public discussions. Never include real contract text, credentials, tokens, or internal approval thresholds in a public issue or pull request.

The skill does not require network access. Review the privacy and retention terms of any model, OCR service, document store, or integration you choose to use with it.

## Reporting a vulnerability

Do not open a public issue for a vulnerability that could expose data or bypass authorization boundaries. Use GitHub's private vulnerability reporting feature for the repository. Include reproduction steps using synthetic data, affected versions, and the expected security boundary.

No production service or response-time guarantee is provided by this open-source project.
